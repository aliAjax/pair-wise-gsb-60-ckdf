# 医疗器械上市后安全信号核查与处置平台

面向医疗器械上市后安全团队的本地工作台，用于合并投诉、维修、不良事件和现场报告，维护证据矩阵、调查任务、风险状态、结论版本和审计轨迹。

## 技术栈

- SvelteKit 2 + Vite + TypeScript
- Skeleton UI + Tailwind CSS
- Svelte stores
- SvelteKit Form Actions
- TanStack Query for Svelte
- Zod

## 主要工作区

- `/`：开放信号、高风险信号、任务和逾期总览
- `/signals`：关键词与多条件筛选、人工登记新信号
- `/signals/[id]`：证据矩阵、状态流转、补充证据、结论版本、重新打开和审计
- `/trends`：发生率趋势与阈值核对
- `/batches`：批号覆盖与报告追踪
- `/trace`：器械标识（UDI-DI）、注册证、生产批号与证据的版本化追溯台账
- `/audit`：跨信号审计时间线、追溯审计报告（冻结依据/复议项）和 JSON 报告导出

## 标识追溯模型（`src/lib/trace`）

把监管核查的四个要素接成可复核的追溯链 `TraceBinding`：器械唯一标识（UDI-DI，可更正版本）
+ 注册证（可换版）+ 一组生产批号（一个标识可关联多个批号，可更正/拆分）+ 信号证据（带内容指纹）。

- **依据变更传播**（`engine.ts` 纯函数状态机 `commit`）：批号更正/拆分、注册证换版、标识更正时，
  未签发（草稿）报告**立即失效**并记录原因；已签发报告**冻结原依据不动**，只追加**复议项**。
- **签发冻结**：签发时把标识版本、注册证版本、批号版本与证据指纹固化为 `FrozenBasis`，
  日后任何更正都能说清"当时引用的是哪一版"。
- **并发控制**：每条链带 `revision` 乐观锁。两个窗口同改同一标识时先到版本生效，
  后到提交被拦截，输入原样保留到冲突面板，可保留先到版本/基于最新重做/放弃。
- **写入故障恢复**（`persistence.ts`）：每次成功写入后保存带校验和的完整追溯快照（保留最近 5 份）；
  写入失败或主状态损坏时从最近完整快照恢复并追加"故障恢复"审计事件，失败写入不产生半截数据。
- **重复导入幂等**：导入载荷按稳定指纹判重，同一载荷重复导入不新增数据、不新增审计。
- **旧数据待核**：迁移数据缺标识版本时进入 `pending_verification`（禁止签发），
  补齐 UDI 版本后批号/证据依据重算，报告转草稿。

页面内可演示：一键模拟双窗口并发、一键模拟写入失败自动恢复、导出/粘贴导入追溯包。

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:18460`。

## 构建、检查与测试

```bash
npm run check
npm run test
npm run build
```

追溯引擎为纯函数状态机，配套 Vitest 单元/集成测试（22 项）覆盖依据传播、乐观并发、
待核重算、快照恢复与导入幂等。

无后端服务，页面使用确定性模拟数据，并将信号、证据、版本、审计记录以及追溯台账持久化到浏览器
`localStorage`。关键表单先经过 SvelteKit Form Action 与 Zod 校验，再写入本地 store。
